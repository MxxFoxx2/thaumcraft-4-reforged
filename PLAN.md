# Thaumcraft 4 Reforged: план порта

Порт Thaumcraft 4.2.3.5 (MC 1.7.10, Azanor) на Minecraft 26.3, 1.21.1 и 1.19.2. Только для личного использования с друзьями: логика и ассеты оригинала переносятся напрямую, механики 1:1.

## Контекст

### Что лежит в `Thaumcraft-1.7.10-4.2.3.5.jar`

- 942 класса, исходников нет. Классы Thaumcraft не обфусцированы, ссылки на Minecraft в SRG (`func_145845_h`, `field_*`), значит после Vineflower и ремапа по MCP `stable_12-1.7.10` получится почти исходный код (тот же путь, что и с TC3).
- Крупнейшие пакеты: `common/tiles` 80, `common/blocks` 71, `client/renderers/*` ~150 (49 TESR, 23 ISBRH, 42 рендерера сущностей, 27+15+6 моделей), `common/container` 26, `client/gui` 24, `client/fx/*` ~40, `common/entities/**` ~110 (монстры 30, чемпионы 16, големы 16, AI ~45, снаряды 12, боссы 6).
- `common/config`: god-классы `ConfigBlocks` (45 блоков с meta-подтипами), `ConfigItems` (108 предметов с meta, ещё 3 поля без реализации), `ConfigEntities`, `ConfigAspects` (теги аспектов), `ConfigRecipes`, `ConfigResearch` (201 исследование).
- Рецепты Thaumcraft: 84 + 5 arcane, 49 тигель, 63 инфузия, 24 инфузионных зачарования, 18 бонусов переплавки, плюс ванильные shaped/shapeless с oredict.
- Ассеты: 292 текстуры предметов, 263 блоков, 217 моделей (в т.ч. 16 `.obj`), 111 звуков (66 событий), 51 аспект, 22 фокуса, post-шейдеры варпа (`blurtc`, `desaturatetc`, `hunger`, `sunscorned`), GLSL в `assets/thaumcraft/shader`.
- Локализация: 22 `.lang`. `ru_RU.lang` полный, включая все 309 страниц исследований (`tc.research_page.*`), отдельный перевод не нужен.
- Зависимости и мёртвый груз: Baubles 1.0.1.10 (7 предметов в `common/items/baubles` на внешнем `baubles.api`), встроенный CodeChicken lib (CCModel, OBJ, освещение), coremod `DepLoader`, `truetyper` (TTF-шрифт), `itemPhotoPlate`, `itemFlyingCarpet`, `WorldGenSilverwoodTreesOld`, код для Thaumic Tinkerer.

### Чем TC4 тяжелее TC3

Ноды как блоки с типами и модификаторами, сеть вис-реле, жезлы из колпачков и стержней, 10 фокусов с апгрейдами, варп с событиями и шейдерами, порча (taint) с распространением и изменением биома, система эссенции с трубами и всасыванием, алтарь инфузии с нестабильностью, чемпионы, культисты, измерение Outer Lands с лабиринтом и боссами, бижутерия (Baubles), 4 своих биома. Это примерно в 2.5 раза больше кода, чем у TC3 (442 класса).

## Цели и принципы

1. Играбельный TC4 на трёх версиях с паритетом контента.
2. Механики, числа, рецепты и тексты 1:1 с декомпилятом. Баги оригинала чиним только если ломают игру (дюп, уничтожение предметов, NPE, рассинхрон, краш сервера), игровые особенности оставляем.
3. Мультиплеер на выделенном сервере обязателен: всё проверяется через `runServer`, утечки клиентских классов недопустимы.
4. Техническая часть на современных API (data components, attachments, payloads, render states на 26.3), JEI.
5. Версионно-зависимый код с первого дня за швами (см. «Архитектура»), чтобы бэкпорт не превращался в переписывание, как было с TC3 (7.7k строк ошибок после каркаса 1.21.1).

## Решения

| Вопрос | Решение |
|---|---|
| Основная версия | `main` = 26.3, бэкпорты цепочкой `main` → `mc/1.21.1` → `mc/1.19.2`, как в TC3 |
| Загрузчики | 26.3: NeoForge 26.3.0.57-beta; 1.21.1: NeoForge 21.1.x; 1.19.2: Forge 43.x через `net.neoforged.moddev.legacyforge` |
| Java | 25 / 21 / 17 (все три уже стоят в `/opt/homebrew/opt/openjdk@*`) |
| Маппинги | 26.3 без обфускации; Parchment `1.21.1/2024.11.17` и `1.19.2/2022.11.27` |
| Сборка | ModDevGradle 2.0.148, Gradle wrapper, configuration cache (в 1.19.2 отключить, если конфликтует) |
| modid, пакет | `thaumcraft`, корневой пакет `thaumcraft`. С TC3 Reforged в одной сборке не уживается, это осознанно |
| Имя и версия | `Thaumcraft 4 Reforged`, `mod_version=4.2.3.5-reforged.1`, jar `thaumcraft-4-reforged-<mc>.jar` |
| Baubles | Свой фасад `platform/Baubles` (амулет, 2 кольца, пояс). На 26.3 свои слоты по образцу Baubles 1.0.1.10 (Curios beta.2 несовместим с NeoForge 26.3.0.37+), на бэкпортах бэкенд выбирается при ветвлении (Curios или те же свои слоты) |
| Зависимости (проверено 2026-10-07) | Curios `17.0.0-beta.2+26.3` / `9.5.1+1.21.1` / `1.19.2-5.1.6.4`; TerraBlender `26.3-26.3.0.0.9` / `1.21.1-4.1.0.1` / `1.19.2-2.0.1.124`; JEI `31.9.0.58` / `19.57.0.451` / `11.68.0.1086` |
| Биомы | Регистрируются JSON-ами на всех версиях, в генерацию оверворлда через TerraBlender (есть на всех трёх версиях) |
| Регистрация контента | Java + `DeferredRegister`, «флаттенинг» meta в отдельные id, состояния в blockstate properties |
| Ресурсы | Python-генераторы в `tools/` с профилями версий (`mcformat.py` из TC3), не datagen |
| Аспекты, исследования, рецепты TC | В Java, генерируются скриптами из декомпилята (`ConfigAspects`, `ConfigResearch`, `ConfigRecipes`), как в TC3 |
| Ванильные рецепты | JSON, генерируются по профилю версии, oredict → теги `c:` / `forge:` |
| Модели | Статичные `ModelRenderer`-модели в JSON (`model_box` из TC3), `.obj` через OBJ loader загрузчика, анимированное в BER/рендерерах сущностей |
| Шрифт книги | Ванильный `minecraft:uniform` вместо `truetyper` |
| Код-стайл Java | Как в TC3: 4 пробела, без комментариев, коммиты `feat:`/`fix:` без соавторства |
| Язык | Все 22 языка конвертируются автоматически, ручные правки только en_us и ru_ru |

## Что берём из TC3 Reforged

Источник: `~/projects/thaumcraft-reforged` (`main` для 26.3, `mc/1.21.1` для бэкпорта).

- **Инструменты:** `tools/remap_srg.py` (поменять путь на MCP 1.7.10), `tools/mcformat.py` (профили 26.3/1.21.1/1.19.2), `tools/gen_resources.py` (blockstates, модели, лут, теги, рецепты, `model_box`), `tools/validate_ids.py`, `tools/backport/rewrite.py` с таблицами замен 1.21.1, `tools/convert_assets.py` и `convert_tags.py`/`convert_research.py` как основа (форматы 1.7.10 другие, переписываются).
- **CI:** `.github/workflows/build.yml` (nightly-релиз на ветку, версия из `gradle.properties`).
- **Инфраструктура кода:** `TcBlockEntity` (`sync()`), `ModNetwork`-фасад, аксессоры компонентов, `ResearchManager`/`AuraManager`-подход к attachment-ам, `GolemInventories` поверх transfer API, `Fx`/`FxProxy` и `ClientFx`, `ModRenderPipelines`, `TcRenderTypes`, `ResearchClientHooks`, `ClientPayloadHandlers`, админ-команды, AT мехов.
- **Ветка `mc/1.21.1` TC3:** `compat/ValueInput`/`ValueOutput`, мосты `loadAdditional`, порт FX/рендер-типов/BER на 1.21.1. Класс, пришедший из TC3, при бэкпорте берётся из этой ветки, а не адаптируется заново.
- **Контент с общей родословной** (логика из TC4-декомпилята остаётся источником истины, код TC3 берётся как заготовка): `Aspect`/`AspectList`, тигель, алембик, банки, верстак, книга исследований (карта, страницы рецептов), таумометр, молнии и лучи (`FXLightningBolt`, `FXBeam`), очки и HUD, защищённые блоки и ключи, бур, зеркала, голодный сундук, мехи и адская печь, левитатор, ухо, огненная мышь, висп, мозговой зомби, башня волшебника, элементальные инструменты, сапоги странника, упряжь (`hoverharness.obj`), база големов и их логистика.
- **Процесс:** `BACKPORT.md` в ветке с sha синхронизации, `rewrite.py` на диффе + `git apply -3`, проверка сервера через `tail -f cmds | ./gradlew runServer`.

## Архитектура

### Швы под три версии (на `main` с первого коммита)

Пакет `thaumcraft/platform` содержит всё, где API трёх версий расходится. Игровая логика ходит только через него. Скрипт `tools/check_seams.py` (запуск в CI) падает, если запрещённые классы импортируются вне `platform/` и `client/platform/`.

| Шов | 26.3 | 1.21.1 | 1.19.2 |
|---|---|---|---|
| `ModNetwork` (send to player/tracking/server/all) | payload + `PacketDistributor` | то же, хендлеры в `playToClient` | `SimpleChannel` + `compat/StreamCodec` |
| `StackData` (жезл, фокус, аспекты в банке, заметки, руны) | data components | data components | NBT |
| `PlayerKnowledge`, `ChunkAura`, `EntityData` | attachments + `.sync()` | attachments + свой payload | capabilities + пакеты |
| `Transfer` (големы, бур, воронки) | `ResourceHandler`/`Transaction` | `IItemHandler`/`IFluidHandler` | то же через `ForgeCapabilities` |
| `Baubles` | свои слоты (attachment, меню, экран) | Curios или свои слоты | то же |
| `Teleport` (Outer Lands, зеркала, фокус) | `TeleportTransition` | `DimensionTransition` | `ITeleporter` |
| `BiomeEdit` (порча, цветок очищения) | `fillbiome`-подход + `ClientboundChunksBiomesPacket` | то же | переотправка чанка |
| `SaveIO` | `ValueInput`/`ValueOutput` | `compat/ValueInput`/`ValueOutput` из TC3 | то же на `CompoundTag` |
| `Registration` (инструменты, броня, топливо, сделки) | `ToolMaterial`, `equipment/`, `trade_set` | `Tier`, `ArmorMaterial` holder, `VillagerTradesEvent` | enum-материалы, события |

### Рендер: геометрия отдельно от API

TC4 рисует почти всё вручную через `Tessellator` (ноды, лучи, трубы эссенции, жидкость в банках, руны инфузии, пузыри, вихри). Это самое дорогое место бэкпорта TC3. Поэтому:

- `client/geom/*`: чистые классы, которые считают вершины (позиция, uv, цвет, нормаль, свет) и пишут в интерфейс `QuadSink`/`LineSink`. В них нет ни одного класса Minecraft, кроме математики JOML.
- `client/platform/*`: реализация sink-ов и рендер-типов под версию (26.3 `SubmitNodeCollector` + `RenderPipeline`, 1.21.1 `VertexConsumer` + `RenderType`, 1.19.2 то же без JOML-перегрузок).
- BER, рендереры сущностей и частицы остаются тонкими: собрали состояние, вызвали `geom`, отдали в sink.

## Риски

| Риск | Что делаем |
|---|---|
| Curios под 26.3 сломан (собран под 26.3.0.7, `ModConfig.Type.COMMON` удалён в FML 12.0.8) | Свои слоты за фасадом `platform/Baubles`, при выходе рабочего Curios можно сменить бэкенд |
| Объём рендера `Tessellator` | `client/geom` + sink-и, порт по одному виду за раз со сверкой скриншотов |
| Формат post-шейдеров разный в каждой версии | Шейдеры генерируются профилем, на 26.3 `post_effect` |
| Смена биома в рантайме | `BiomeEdit` за швом, тест на выделенном сервере с двумя игроками |
| Outer Lands: API `ChunkGenerator` и телепорт меняются | Генератор лабиринта отдельно от `ChunkGenerator`-обёртки, `platform/Teleport` |
| `MazeThread` в оригинале асинхронный | Генерация синхронно или с очередью на главный поток, без доступа к миру из потока |
| Нагрузка от нод, порчи и големов на сервере | Тики через менеджеры на главном потоке, лимиты как в оригинале, профилирование `spark` |
| Мультиплеерные рассинхроны (вис, знания, банки) | Синхронизация только через `ModNetwork`, тест с двумя клиентами |
| Ассеты Azanor (ARR) | Репозиторий для себя и друзей, релизы не распространяются публично |

## Исполнение

- Большие фазы режутся на волны непересекающихся наборов файлов и выполняются параллельными Sonnet-агентами в своих worktree (не больше 4 одновременно из-за памяти Gradle). Между волнами: слияние, `compileJava`, `runServer`; визуальную проверку в `runClient` делаешь ты.
- Типичное деление фазы: A) реестр и предметы, B) блоки, BE и меню, C) сущности/логика, D) клиент (экраны, рендер, `geom`). Генераторы в `tools/` всегда у одного агента.
- Каждый агент получает: этот план, строки `INVENTORY.md` своей части, пути в `reference/decompiled`, код-стайл и список своих файлов.
